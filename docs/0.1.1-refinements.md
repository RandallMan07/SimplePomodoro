## Freesound downloader

Branch/worktree: `hotfix-sound-downloader`, `../SimplePomodoro-worktrees/hotfix-sound-downloader`.

- Replace Commons as the default source with Freesound. Use the current `/apiv2/search/` API, duration/license filters, creator/source/license metadata, and preview-format downloads. Originals require OAuth and are outside this refinement; label downloaded previews accurately.
- Let the user enter an API key in a password field, with account/application credential links and Save/Clear actions. Allow an environment override. Store a saved key separately from ordinary settings in a private, atomically written XDG config file with mode 0600. Never put keys in URLs, attribution metadata, repository files, or logs; attach authorization only to API requests, never preview hosts/redirects.
- Add **Search in browser**, usable without an API key, opening Freesound with the current encoded search and short-sound filters. Keep browser links free of credentials.
- Default searches to reminder effects up to three seconds. Provide a countdown-pip option up to 300 ms with near-immediate onset, validating available metadata. Show missing metadata or filtering limitations clearly. Preserve cancellation, bounded downloads, no-overwrite publication, library refresh, and attribution sidecars.
- This provider change reduces unsuitable source material; it does not introduce onset editing or sample-accurate playback. Preparing/decoding/trimming excerpts is a separate audio refinement if the user still needs it after testing short effects.
- Focused checks: provider parsing/filters, credential permissions and authorization scope, browser URL encoding, fake-HTTP downloads, and a short GTK form/lifecycle smoke. No live authenticated success can be claimed without a locally supplied API key.

References: [Freesound resources](https://freesound.org/docs/api/resources_apiv2.html), [authentication](https://freesound.org/docs/api/authentication.html), [browser filter syntax example](https://freesound.org/forum/bug-reports-errors-and-feature-requests/42946/?page=1).

## Summary widget interaction and restoration

Branch/worktree: `hotfix-summary-widget`, `../SimplePomodoro-worktrees/hotfix-summary-widget`.

- **Placement:** user explicitly chose flush against the panel's bottom edge. Remove the six-pixel gap and continue respecting the top panel's reserved area. Do not overlay or cover Waybar.
- **Hover:** remove click-to-pin behavior. Mouse clicking the arrow must not hold the summary open after the pointer leaves. Preserve keyboard access through focus-visible behavior; ordinary mouse focus does not hold expansion.
- **Animation:** use independent fixed-size arrow and summary layer surfaces. Never resize/reanchor the arrow as the summary appears. Fade the summary content/background smoothly; keep its layer mapped at a fixed position to avoid compositor map/unmap bounce. When fully transparent, set an empty input region and disable keyboard interaction so the invisible surface does not intercept desktop clicks.
- **Restoration:** capture the actual main window's floating/tiled state, geometry and workspace before hiding it. On restoring the full interface, recover the saved floating position/size or return it to the compositor's tiled layout. If capture is unavailable, fall back to content-sized floating placement on Hyprland; preserve GTK size on other supported desktops.
- Serialize bounded compositor IPC with initial placement, capture and restore to prevent races. Match only the current process/application, validate selectors and coordinates, and ignore stale callbacks after reactivation/close. Do not modify desktop configuration.
- Keep both layer surfaces on the same monitor, exclusive zone zero, with one owner/timer/tick loop. Start transparent before mapping to avoid a first-frame flash and clean up both surfaces/callbacks on exit or return to the full window.
- Focused checks: window-state IPC and pure summary tests plus a short GTK smoke for construction, hover/fade/input regions, and restoration lifecycle. The user judges animation feel and actual desktop interaction.

Reference: [GTK4 layer-shell API](https://wmww.github.io/gtk4-layer-shell/gtk4-layer-shell-GTK4-Layer-Shell.html).

## Acceptance procedure

Close other SimplePomodoro instances before testing a branch. For the downloader, open Sound library → Download sounds, try browser search without a key, save a local Freesound key, search for a short beep, preview/download and assign it. Test the countdown-pip filter separately and listen to the existing 3–2–1 test.

For the widget, check that the arrow touches the panel's bottom edge, hover in/out repeatedly, click and leave to confirm there is no pin, and move over the faded-out bar area to confirm desktop clicks work. Restore the full window after changing its size/position and after tiling it; compare its state before and after. Report approval or requested changes for each branch separately.
