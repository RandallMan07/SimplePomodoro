## Scope and design

Save versioned session state in `$XDG_STATE_HOME/simplepomodoro/session.json`, normally `~/.local/state/simplepomodoro/session.json`, separately from preferences. Include timer configuration, phase, round, fractional remaining time, running/paused/finished state, warning state, and a wall-clock save timestamp. Write atomically at user actions and phase transitions, with periodic checkpoints while running.

Live operation continues to use monotonic deadlines. On reopening, a running session advances by wall-clock time elapsed since its snapshot. A paused session remains paused with unchanged remaining time. Backward clock movement contributes no elapsed time; long absences finish the bounded session. This intentionally adds closed-time progress without changing the live monotonic clock's suspend behavior. Historical phase notifications and sounds must not replay.

Validate stored types, finite numeric values, bounds, and coherent phase/configuration state. Invalid/unreadable state starts safely from preferences; write failures are nonfatal. Restored configuration must populate controls without resetting the restored timer.

Persistence is always enabled. Closing automatically snapshots before GTK/audio cleanup stops live operation, without a save confirmation. Paused close retains paused state. **Reset** explicitly discards the active countdown. If saving fails, keep the window open with an error so the latest running/paused state is not silently lost. This supersedes the initial Save and close / End session confirmation design at the user's request on 2026-10-31.

## Acceptance

State-isolated GTK checks must never overwrite the user's real session.
