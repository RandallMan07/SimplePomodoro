# Persistent summary reminder mode

Date: 2026-10-31. User requested a separate click mode while retaining the existing hover behavior. Agent submitted a plan and coordinator approved it before implementation. Branch/worktree: `hotfix-summary-widget`, `../SimplePomodoro-worktrees/hotfix-summary-widget`. Implementation `0ff489b` and focused coordinator review complete; user acceptance remains required.

## Interaction

- **Hover mode remains:** the arrow is flush below the top panel. Hover shows the summary below the arrow with a six-pixel gap; leaving both surfaces collapses it with the existing grace period and fade.
- **Click the arrow:** enter a persistent reminder mode. Hide the arrow, fade the summary out, reposition it while transparent to six pixels below the panel, reveal a minimize-back button, then fade the summary in. It stays visible after pointer leave as a reminder of remaining time.
- **Minimize back:** fade the persistent summary out, restore its hover placement, hide the extra button and show the arrow again. Return to the collapsed hover state; a fresh hover opens the summary.
- Keep pause/resume, Open full timer, Escape/full-window restoration and the saved main-window configuration behavior. The full application header still contains only compact and close; the new minimize action belongs only to the persistent summary bar.

## Implementation constraints

Use the existing two layer surfaces, with empty input regions and keyboard interaction disabled on transparent/inactive surfaces. Keep the hidden arrow mapped to retain configured height and avoid compositor remap animation. Reposition and change summary controls while fully transparent, then allow layout to settle before fading in. No desktop configuration changes.

Transition completion must be invalidated on disposal or superseding actions. Mouse leave cannot collapse persistent mode. Minimizing clears stale pointer/focus ownership so a prior hover does not immediately reopen the bar. Preserve keyboard access and avoid competing activation handlers on the arrow.

## Focused checks and acceptance

Update the existing GTK smoke with persistent entry, pointer leave, minimize-back, repeated toggles, configured margins, input/keyboard state and cleanup. Keep checks light; the user assesses animation feel. Manually hover as before, click the arrow, leave the reminder visible, minimize it back, hover again, and restore the full window. Neither the implementation plan nor passing checks constitutes user acceptance or permission to merge/tag.
