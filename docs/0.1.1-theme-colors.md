# Desktop palette decisions

Status: implementation reviewed and coordinator checks passed; awaiting user acceptance. Branch: `hotfix-theme-colors`. Implementation commit: `1bcd253`.

## Scope and design

Follow `$XDG_CONFIG_HOME/omarchy/current/theme/colors.toml` when present. Hyprland itself does not define a universal application palette: Omarchy's active theme supplies this machine's shared color source. Use semantic colors and ANSI aliases, validate each value as a hexadecimal RGB color, and derive readable surfaces and foreground contrast. Missing or invalid themes retain the existing usable palette.

Use one palette for GTK's application-specific CSS colors and Cairo's timer ring/ticks. Respect the palette's light/dark mode. Detect active-theme symlink switches and file changes using a low-frequency stat check; read and rebuild styling only after changes. Remove providers and polling sources on close. Do not write to Omarchy, GTK, or Hyprland configuration.

## Acceptance

Test semantic and ANSI input, malformed/missing colors, light/dark contrast, fallback behavior, theme reload, and GTK stylesheet parsing. Check that both the countdown ring and native interface follow a synthetic palette and a changed palette without restarting.

The coordinator reviewed the implementation and independently passed all 29 unit tests plus the desktop GTK smoke check. The smoke check applies synthetic light and dark palettes and confirms live reload. Screenshot: [active host palette](screenshots/0.1.1-theme-colors.png).

Other Hyprland setups without Omarchy's palette file retain the default colors; arbitrary compositor configurations are not parsed.
