# Version 0.1.1 feature review plan

Status: implementation requested; each functionality requires user acceptance before integration. No release tag exists for this batch yet.

## Branches and acceptance boundaries

| Branch | Scope | Dependencies |
| --- | --- | --- |
| `hotfix-sound-library` | Built-in and local sound choices, library folder, preview/test form, synchronized countdown alerts | Baseline |
| `hotfix-sound-downloader` | Search a free sound gallery, show licensing/provenance, download into local library | Sound-library interface |
| `hotfix-theme-colors` | Follow current desktop palette, including Cairo timer colors | Baseline |
| `hotfix-session-persistence` | Persist active and paused timers, resume accurately after reopening | Baseline |
| `hotfix-summary-widget` | Explicit minimize and compact-widget controls, persistent top-center arrow, hover summary | Baseline; desktop support must be verified |

Each implementation starts only after the coordinator reviews its agent's plan. The coordinator owns decision documentation and final verification. Agents use isolated worktrees; no feature is merged into main before explicit user acceptance.

## Product intent

- Keep the native Python/GTK4/libadwaita/GStreamer stack and system-package distribution.
- Sound customization provides separate warning, phase-change, and completion choices, with generated defaults available without downloads. The user can supply a local folder and audition sounds before assigning them. Optional countdown mode emits short cues aligned to the last three whole seconds before a phase boundary, without replaying missed cues after delays.
- Gallery browsing/downloads are explicit user actions. Show source and license details and preserve attribution alongside downloaded files. Ordinary timer operation remains offline. Avoid account/API-key setup where a usable public gallery permits anonymous access.
- Follow the installed Omarchy palette when present, with validated local color values and a usable default elsewhere. Apply colors consistently to GTK and the Cairo drawing. Do not modify desktop configuration.
- An active timer should account for elapsed time while the application is closed, and a paused timer should remain paused. Restore the full configuration and phase/round state. Use atomic local state writes and validate stored data. Do not replay historical sounds on reopen. Closing and explicitly ending/resetting a session need distinct semantics.
- Widget mode shares the timer with the main window. An arrow remains visible at the top center and expands on hover/focus into phase and time remaining, with useful controls and a route back to the full window. Always-on-top and workspace behavior depend on compositor support; test actual Hyprland behavior and document fallback behavior. Minimize must use a compositor-supported action or explain an unavailable action in the UI.

## Release gate

For every branch record the commit reviewed, automated checks, graphical evidence when available, known limitations, and manual acceptance steps. User approval is per functionality in a later message. Update the application/package/archive version together only during approved integration, then create an annotated `0.1.1` tag after release checks.
