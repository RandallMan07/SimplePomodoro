## Current interaction

Header controls now offer only compact mode and close. The minimize/hide control and its explanatory tooltip were removed at the user's request. The optional GTK4 layer-shell dependency supplies overlay surfaces, so unsupported desktops retain the main window.

The user chose the arrow flush against the top panel's bottom edge: top margin zero while respecting Waybar's reserved area. The arrow and summary are separate layer surfaces on the main window's monitor. The arrow never resizes/reanchors during hover. The summary remains mapped and fades its opacity over 160 ms, avoiding repeated compositor map/unmap animation. In collapsed hover mode it has an empty input region and no keyboard interaction, so the transparent area cannot intercept desktop input.

The summary's top margin now comes from the arrow's configured Gdk surface height plus a six-pixel gap, not its potentially zero pre-allocation GTK height. Both surfaces share the arrow's actual monitor, and the summary maps only once that height is valid. This fixes the overlap reported in the user's screenshots while preserving the liked placement and fade. The six-pixel gap was added in a subsequent user-requested polish; the existing 180 ms crossing grace allows the pointer to move across it.

Mouse hover opens the summary; leaving both surfaces closes it after a short crossing grace period. Clicking the arrow now enters a separate persistent reminder mode: hide/disable the arrow, fade the summary out, reposition it invisibly to six pixels below the panel, then fade it back in with a minimize-back control. The reminder stays visible when the pointer leaves. Minimize returns to the arrow and collapsed hover mode. Keyboard Return/Space can enter the reminder and transfer focus to its controls; mouse activation does not steal keyboard focus. The summary shows phase, time left, round and pause/resume/open controls, sharing the main timer and tick loop. Escape, Open full timer or launcher activation restores the main interface. See [reminder-mode decisions](0.1.1-widget-reminder-mode.md).

## Full-window restoration

Before hiding the main window, capture its current Hyprland floating/tiled state, size, position and workspace. Restore the saved geometry for floating windows or return tiled windows to the compositor's layout. If capture is unavailable, use content-sized floating placement on Hyprland. Exact tiled sibling order, fullscreen modes and layout geometry are not separately serialized.

A single bounded compositor worker orders initial placement, capture and restore. Match only the current process and application class with validated window selectors. The main window stays available during capture; cycle tokens prevent a late capture callback from hiding a newly reactivated or closing window. Dispose both surfaces and pending fade/collapse callbacks on cleanup. No desktop configuration is modified.

References: [GTK4 layer-shell](https://wmww.github.io/gtk4-layer-shell/gtk4-layer-shell-GTK4-Layer-Shell.html), [GTK minimize semantics](https://docs.gtk.org/gtk4/method.Window.minimize.html).
