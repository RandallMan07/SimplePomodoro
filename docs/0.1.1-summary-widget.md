# Header controls and summary widget decisions

Status: requested refinements implemented and coordinator-reviewed; awaiting user functional acceptance. Branch: `hotfix-summary-widget`. Initial implementation: `1a33918`. Refinements: `0f135fb`. Independent of palette and persistence branches.

## Current interaction

Header controls offer compact mode and minimize alongside close. Hyprland uses the recoverable arrow for minimize; other desktops receive a native GTK minimize request. The optional GTK4 layer-shell dependency supplies overlay surfaces, so unsupported desktops retain the main window and explain unavailable widget support.

The user chose the arrow flush against the top panel's bottom edge: top margin zero while respecting Waybar's reserved area. The arrow and summary are separate fixed layer surfaces on the main window's monitor. The arrow never resizes/reanchors during hover. The summary remains mapped and fades its opacity over 160 ms, avoiding repeated compositor map/unmap animation. At rest it has an empty input region and no keyboard interaction, so the transparent area cannot intercept desktop input.

Mouse hover opens the summary; leaving both surfaces closes it after a short crossing grace period. Click-to-pin was removed at the user's request. Keyboard focus-visible navigation remains accessible, while mouse-assigned focus cannot hold the summary open. The summary shows phase, time left, round and pause/resume/open controls, sharing the main timer and tick loop. Escape, Open full timer or launcher activation restores the main interface.

## Full-window restoration

Before hiding the main window, capture its current Hyprland floating/tiled state, size, position and workspace. Restore the saved geometry for floating windows or return tiled windows to the compositor's layout. If capture is unavailable, use content-sized floating placement on Hyprland. Exact tiled sibling order, fullscreen modes and layout geometry are not separately serialized.

A single bounded compositor worker orders initial placement, capture and restore. Match only the current process and application class with validated window selectors. The main window stays available during capture; cycle tokens prevent a late capture callback from hiding a newly reactivated or closing window. Dispose both surfaces and pending fade/collapse callbacks on cleanup. No desktop configuration is modified.

References: [GTK4 layer-shell](https://wmww.github.io/gtk4-layer-shell/gtk4-layer-shell-GTK4-Layer-Shell.html), [GTK minimize semantics](https://docs.gtk.org/gtk4/method.Window.minimize.html).
